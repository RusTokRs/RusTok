# Continuous Code Review & Remediation Guidelines (ACRE)

This document establishes the canonical protocol for AI agents, automated schedulers, and contributors performing continuous code reviews and auto-remediations across the RusToK codebase.

The goal of the **Autonomous Continuous Review & Remediation Engine (ACRE)** is to eliminate technical debt, enforce invariants, and eliminate antipatterns without causing architectural drift or refactoring thrash.

---

## 1. Core Principles & Governance

All automated remediations MUST comply with [AGENTS.md](../../AGENTS.md), [patterns-vs-antipatterns.md](patterns-vs-antipatterns.md), and [KNOWN_PITFALLS.md](../ai/KNOWN_PITFALLS.md).

### The Invariants

1. **Convergence over Ping-Pong:**
   - Changes are strictly bounded to the identified finding and rule.
   - Do not refactor surrounding code or re-format unrelated methods "to make it look cleaner."
2. **Zero-Legacy Policy (AGENTS.md §13):**
   - Implement the canonical target architecture directly.
   - Do not introduce backward-compatibility wrappers, deprecated aliases, fallback chains, or fake adapters.
3. **No Stubs or Suppressions (AGENTS.md §14):**
   - **STRICTLY PROHIBITED:** Adding `#[allow(dead_code)]`, `#[allow(unused)]`, `@ts-ignore`, `@ts-expect-error`, `todo!()`, or `unimplemented!()`.
   - **STRICTLY PROHIBITED:** Deleting existing tests to make a build or linter check pass.
4. **Write-Side & Multi-Tenant Correctness (AGENTS.md §7):**
   - Every database query touching domain data must be strictly scoped by `tenant_id`.
   - Domain mutations that emit events must use `publish_in_tx()` within the database transaction.

## 2. Review Pipeline Lifecycle

The remediation lifecycle operates in five deterministic phases:

```
[1. Scanner]  -->  [2. Backlog]  -->  [3. Agent Worker]  -->  [4. Gatekeeper]  -->  [5. Commit/PR]
scan_codebase     .review_backlog    review_orchestrator   verify-remediation-gate
```

### Phase 1: Scan
Deterministic rules defined in `scripts/maintenance/review_rules.toml` are evaluated by `scripts/maintenance/scan_codebase.py`. Findings are categorized by tier:
- **Tier 0:** Critical Correctness, Multi-Tenancy & Panic Prevention (`SEC-TENANT-01`, `REL-UNWRAP-01`, `SUPP-FORBIDDEN-01`).
- **Tier 1:** Architecture, Transports & Event Consistency (`EVENT-OUTBOX-01`, `ERR-ANYHOW-01`, `LOG-RAW-PRINT-01`).
- **Tier 2:** Observability & Code Metrics (`OBS-INSTRUMENT-01`, `METRIC-FN-LEN-01`, `PERF-CLONE-CHURN-01`).

### Phase 2: Backlog
Findings are stored in `.review_backlog.json` prioritized by Tier (0 → 1 → 2).

### Phase 3: Agent Remediation
An agent receives an atomic task brief generated by `python scripts/maintenance/review_orchestrator.py brief`.
The agent modifies only the necessary files to address the finding cleanly.

### Phase 4: Gatekeeper Check
Before any remediation commit is accepted, the change MUST pass:
```bash
python scripts/verify/verify-remediation-gate.py --files <path/to/modified_file>
```
The gatekeeper verifies:
1. **Diff Invariant Check:** Verifies no disallowed suppression (`#[allow]`, `@ts-ignore`) or test deletions exist.
2. **Architecture Dependency Guard:** Runs `scripts/architecture_dependency_guard.py` to prevent unauthorized cross-crate imports.
3. **Crate Clippy & Compiler Gate:** Runs `cargo clippy --package <crate> --all-targets -- -D warnings`.

### Phase 5: Commit & Reporting
The change is committed with a structured message:
```
fix(review): [RULE-ID] resolve <description> in <module>
```

## 3. Tooling Reference

| Tool | Location | Purpose |
|---|---|---|
| **Rules Catalog** | `scripts/maintenance/review_rules.toml` | Canonical definitions of review rules, regexes, heuristics, and remediation contracts. |
| **Scanner** | `scripts/maintenance/scan_codebase.py` | Fast codebase scanner producing `.review_backlog.json`. |
| **Orchestrator** | `scripts/maintenance/review_orchestrator.py` | CLI driver for dispatching next tasks, generating agent briefs, and running gates. |
| **Gatekeeper** | `scripts/verify/verify-remediation-gate.py` | Automated pre-commit verification gate enforcing AGENTS.md §14 and architecture rules. |

---

## 4. Execution Commands

### Scan specific module
```bash
python scripts/maintenance/scan_codebase.py --target crates/modules/rustok-forum --summary
```

### Scan specific rule (e.g. panic prevention)
```bash
python scripts/maintenance/scan_codebase.py --rule REL-UNWRAP-01 --summary
```

### Fetch next task brief for an AI agent
```bash
python scripts/maintenance/review_orchestrator.py brief --tier 0
```

### Run Gatekeeper on changed files
```bash
python scripts/verify/verify-remediation-gate.py --files crates/modules/rustok-forum/src/service.rs
```
