## 2026-08-03 continuation audit

Slice 88 unblocked the canonical writer by registering:

```text
blog.comments_delegation_schedule.replacement_succeeded / v1
```

A fresh audit of the canonical outbox boundary found one remaining ownership
gap:

- ordinary `TransactionalEventBus::publish_contract_in_tx_with_envelope_id`
  creates a new envelope identity for every call;
- `sys_events.id` is already the canonical primary key and therefore the
  correct serialization point for one exact source identity;
- the Blog audit `request_id` is already durable, non-nil, and explicitly owned
  by the slice-87 publication document as the handoff idempotency identity;
- no second Blog receipt table or outbox-specific idempotency table is required
  to implement exact replay admission;
- `rustok-outbox` must own the generic row insert/read/compare algorithm because
  only it owns canonical `sys_events` persistence and row consistency checks.

## Slice 89 — canonical typed write-once writer

### Exact envelope identity construction

`ContractEventEnvelope` gains:

```text
ContractEventEnvelope::new_with_envelope_id(
    envelope_id,
    tenant_id,
    actor_id,
    event,
)
```

The supplied UUID is used as both:

```text
envelope.id
envelope.correlation_id
```

The constructor still validates:

- non-nil envelope, tenant, and optional actor identities;
- the sealed typed event;
- registered event type and schema version;
- payload metadata consistency;
- trace bounds.

It does not change the serialized envelope fields or the committed event
contract digest artifact. Ordinary publications continue to use generated
ULID-backed UUIDs. Exact identity construction is reserved for an owner that
already has one durable idempotency UUID.

### Generic canonical outbox write-once API

`rustok-outbox` gains:

```text
TransactionalEventBus::publish_contract_once_direct_in_tx_with_envelope_id
```

and the closed error surface:

```text
ContractEventWriteOnceError::Conflict
ContractEventWriteOnceError::Unavailable
```

The API accepts only a sealed `EventContract` and a caller-owned transaction.
It never accepts raw JSON, arbitrary event names, a database connection outside
the owner transaction, or a direct transport handle.

### Write-once algorithm

The canonical algorithm is:

1. construct one validated typed envelope whose ID is the caller-provided
   durable identity;
2. insert the canonical row into `sys_events` with:

   ```text
   ON CONFLICT (id) DO NOTHING
   ```

3. read the winning row through the same transaction;
4. compare duplicated row event type/schema version with the decoded envelope;
5. validate the decoded registered envelope;
6. admit exact replay only when all stable facts match;
7. return the exact canonical envelope UUID.

Stable replay comparison includes:

- envelope ID;
- correlation ID;
- causation ID;
- tenant ID;
- actor ID;
- event type;
- schema version;
- validated typed payload.

Replay comparison deliberately ignores:

- envelope timestamp;
- trace ID;
- `sys_events` delivery status;
- retry count, claim, next-attempt, last-error, dispatch, and row-created
  metadata.

Timestamp and trace are generated by the first winning writer. Delivery state is
owned by `OutboxRelay` and must not turn an exact source replay into a second
canonical event.

### Conflict and unavailable classification

`Conflict` means the exact requested UUID already identifies different stable
canonical facts, including a different tenant, actor, causation identity,
correlation identity, event type, schema version, or typed payload.

`Unavailable` covers:

- envelope construction or registered validation failure;
- canonical insert or read failure;
- a missing row after the write-once insert;
- unreadable or invalid stored envelope JSON;
- mismatch between canonical row metadata and its decoded envelope;
- integer conversion or other infrastructure-safe adapter failure.

Raw database, serialization, or validation details remain private logs and are
not returned through the Blog writer port.

### Blog Comments canonical writer adapter

The server adds:

```text
RustokOutboxCommentsTcpDelegationScheduleAuditCanonicalWriter
```

It implements:

```text
CommentsTcpDelegationScheduleAuditCanonicalWriter
```

The adapter maps the bounded slice-87 publication document into:

```text
BlogCommentsDelegationScheduleAuditEvent::ReplacementSucceeded
```

It uses:

```text
publication.request_id() == canonical envelope UUID
publication.request_id() == canonical correlation UUID
publication.request_id() == event payload request_id
```

It keeps:

- control-plane tenant in envelope metadata;
- actor in envelope metadata;
- the fixed state key and bounded audit facts in the typed payload;
- direct-user/service principal semantics;
- closed `Conflict|Unavailable` owner errors.

It does not construct an `OutboxTransport`, start a relay, or publish directly
to Iggy, HTTP, a broker, or another transport.

### Signed wire range

The slice-87 publication DTO stores host values as `u64`, while the registered
v1 event wire uses positive `i64` fields.

Slice 89 therefore rejects timestamps and generations above `i64::MAX` at the
publication admission boundary. The adapter retains checked conversions as a
second fail-closed guard.

### Source coverage

Focused source coverage is added for:

- explicit exact envelope identity and correlation identity;
- replay comparison that ignores only timestamp/trace metadata;
- mismatch rejection for envelope scope and typed payload;
- SQLite canonical insertion, exact replay, and mismatched reuse conflict;
- exact Blog publication-to-event mapping;
- closed outbox-to-Blog error mapping;
- signed wire-range admission.

These tests are committed for maintainers but are not executed by this slice's
default test policy.

- canonical relay, retry, DLQ, or cleanup execution;
- PostgreSQL concurrency or ambiguous-commit evidence;
- Rust unit/integration test execution;

## Ownership retained

- Blog owns the already-durable successful replacement audit fact and source
  handoff lifecycle.
- The server owns publication DTO admission, control-plane tenant choice, and
  the concrete Blog-to-canonical writer adapter.
- `rustok-events` owns sealed event payloads and validated envelope construction.
- `rustok-outbox` owns canonical write-once persistence, row consistency,
  relay, retry, DLQ, and canonical retention.
- Maintainers own test, verifier, PostgreSQL, runtime, and production validation.
