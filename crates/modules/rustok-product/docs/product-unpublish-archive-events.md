# Product unpublish and archive lifecycle events

Status: `source_ready_digest_regeneration_pending`.

## Problem

Withdrawing a product from sale and retiring it from circulation are separate lifecycle facts, but
the owner published neither of them: `unpublish_product` emitted `product.updated`, and `Archived`
was reachable only through `updateProduct(status: ARCHIVED)` with no owner command and no event.
Consumers therefore could not distinguish "the operator edited something" from "the product is no
longer visible", and the "archive before removal" rule had no first-class operation behind it.

## Published contract

Two root events were added to the closed `DomainEvent` contract, both schema version `1` and both
carrying exactly `product_id: Uuid`:

| Event type | Meaning | `published_at` | Status after the command |
|---|---|---|---|
| `product.unpublished` | The product was withdrawn from sale; localized/storefront visibility must converge. | cleared | `Draft` (or the status supplied through `updateProduct`) |
| `product.archived` | The product is retired from circulation and is excluded from every non-archived scope. | cleared | `Archived` |

Both types are published by the owner inside the same write transaction as the product row update,
are classified as root events, `affects_index() == true`, and are validated by
`validate_not_nil_uuid("product_id", ...)`.

## Emission points

| Path | Event |
|---|---|
| `CatalogService::unpublish_product` | `product.unpublished` |
| `CatalogService::archive_product` | `product.archived` |
| `CatalogService::update_product` becoming `Active` | `product.published` |
| `CatalogService::update_product` becoming `Archived` | `product.archived` |
| `CatalogService::update_product` leaving `Active` for any other status | `product.unpublished` |

`update_product` still emits `product.updated` first: the generic event keeps carrying "something
changed", while the lifecycle event states which transition happened.

## Surfaces

| Layer | Unpublish | Archive |
|---|---|---|
| Owner command | `CatalogService::unpublish_product` | `CatalogService::archive_product` |
| Owner port | `ProductCatalogCommandPort::unpublish_product` | `ProductCatalogCommandPort::archive_product` |
| Commerce GraphQL | `unpublishProduct(idempotencyKey, id)` | `archiveProduct(idempotencyKey, id)` |
| Commerce REST | `POST /admin/products/{id}/unpublish` | `POST /admin/products/{id}/archive` |

Every surface requires a caller-owned `Idempotency-Key` and maps owner failures onto the bounded
public error vocabulary (`verify-commerce-product-{graphql,rest}-lifecycle-command-cutover.mjs`).

## Consumer routing

- `rustok-search` ingestion projects both event types through `upsert_product`, which re-derives
  storefront visibility from the owner state, so an unpublished or archived product disappears from
  search results instead of staying indexed.
- Product Index refresh treats both as lifecycle events: `product_locale_refresh_target` returns
  the product for both types, so the locale refresh ledger of the Index contract is advanced the
  same way as for `product.published`.
- The translation-change journal is deliberately untouched: a pure status transition rewrites no
  translation row, so nothing invalidates translated storefront copy.
- `ProductIndexRefreshPublication` accepts both as valid root events for the causation check.

## Release gate

The committed `crates/libs/rustok-events/contracts/event-contract-digests.json` artifact is a
release gate and is **not** regenerated by hand. The four wire digests of this change must be
produced on this exact branch and committed before merge:

```
cargo run --locked -p rustok-events --example event_contract_digests -- --write
```

`cargo test -p rustok-events` fails with `published_event_contract_matches_committed_release_artifact`
until that command runs, which is the intended admission signal for a wire-contract change.
