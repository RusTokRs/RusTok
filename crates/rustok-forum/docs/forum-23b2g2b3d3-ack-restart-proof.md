# FORUM-23B2G2B3D3 Iggy acknowledgement/restart proof

## Status

`source_ready_maintainer_execution_pending`

This slice adds the next executable subset of the
`FORUM-23B2G2B3D` runtime-evidence matrix. It combines the external Iggy
persistent consumer-group cursor with the Search-owned PostgreSQL ingress and
proves result-first redelivery when acknowledgement does not commit the source
offset.

The machine-readable proof contract is:

```text
crates/rustok-forum/contracts/forum-search-versioned-invalidation-ack-restart-proof.json
```

The executable test is:

```text
crates/rustok-search/tests/forum_versioned_invalidation_ack_restart_iggy.rs
```

Successful execution writes:

```text
target/forum-search-versioned-invalidation-ack-restart-evidence.json
```

The artifact is generated by the executable test only, records the exact Git
source commit, and must not be hand-edited.

## Covered scenario

The test publishes two caused
`forum.search_projection.invalidation_issued` envelopes to one external Iggy
`domain` topic partition. It uses the exact production consumer-group identity
`rustok-search-forum-projection-v1`; only the isolated evidence stream name is
unique. The first delivery is admitted through `ForumSearchContractIngress`
before acknowledgement.

The proof then replaces only the returned acknowledgement token with another
validly encoded Iggy token whose consumer identity does not match the
outstanding delivery. The cursor rejects that token before `store_offset`, so
the exact source offset remains uncommitted. This is the deterministic injected
ACK failure for the harness; it does not claim a network outage or server worker
retry execution.

After the first cursor and transport are dropped, the test reopens the exact
same production consumer group and requires:

- the same broker offset;
- the same typed envelope ID;
- the same legacy root causation ID;
- the same exact raw payload;
- one durable `search_projection_inbox` row;
- the original positive `ingest_sequence` unchanged.

The restarted cursor then acknowledges the redelivery successfully and must
advance to the second published typed event. That continuation check prevents a
false proof that merely observed the first delivery twice without committing it.

## Compatibility and degraded mode

This slice adds only an integration test, a dev dependency, contracts,
documentation and a static verifier. It does not change production migrations,
event schemas or digests, public DTOs, Search query behavior, broker topology,
the default-off server consumer flag, or the mandatory legacy
`index.reindex_requested` path.

The test skips explicitly when either the PostgreSQL URL or external Iggy
address is absent. A skip does not create the evidence artifact and is not a
successful runtime claim.

## Deliberate boundary

D3 does not run the server-owned consumer loop or its retry backoff. It does not
prove poison-receipt persistence, DLQ publication/deduplication, projector
execution, owner-checkpoint advancement, multi-process locking, deletion/ACL
ordering, Search-disabled recovery, or `LINK-FORUM-03` completion.

Those remain separate bounded runtime slices under the parent D0 protocol.
