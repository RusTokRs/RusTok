## Covered scenario

The test preloads `search_projection_inbox` with one valid legacy
`index.reindex_requested` row. It then publishes a valid caused
`forum.search_projection.invalidation_issued` envelope whose causation UUID
matches that row while tenant, scope and payload identity deliberately differ.

Using the production Forum Search consumer group
`rustok-search-forum-projection-v1` and topic `domain`, the first delivery must:

1. decode and validate as a sealed typed event;
2. fail `ForumSearchContractIngress` with the non-retryable stable code
   `forum.search_projection.contract_inbox_identity_conflict`;
3. leave the pre-existing inbox row byte-for-byte unchanged and unique;
4. derive one connector delivery UUID from exact broker coordinates and typed
   bytes using the same schema-validation identity path as the server worker;
5. publish one deterministic DLQ message carrying that UUID as its Iggy broker
   message identity;
6. persist one poison receipt in `published` before source acknowledgement.

The first source cursor is dropped without acknowledgement. Reopening the same
consumer group must redeliver the exact offset, typed envelope, root causation
identity and raw bytes. The ingress conflict must remain unchanged, the same
poison identity must be derived, and `reserve_and_claim` must return
`AlreadyPublished` while preserving the first observed attempt count. No second
physical DLQ message may appear.

Only after the durable terminal result is reused does the test acknowledge the
source and mark the receipt `acknowledged`. A following valid typed invalidation
must then reach the shared Search inbox and receive a later source offset.

## Worker protocol alignment

The server worker's private `semantic_poison_descriptor` constructs semantic
poison identity from `ConsumedContractDecodeFailure::new` with
`ContractDecodeFailureKind::SchemaValidation`, then builds a `DlqEntry` with the
same exact bytes, stable ingress error and connector delivery UUID. The test
reproduces this public protocol directly; no new worker API or test-only
production seam is introduced.

## Compatibility and degraded mode

This slice retains only a host-owned integration test, contracts, documentation
and a static verifier. The server package already owns direct Search, Iggy and
connector dependencies, so the proof adds no package edge and requires no
`Cargo.lock` change. It does not change production Rust paths, migrations,
event schemas or digests, public DTOs, Search queries, broker topology, the
default-off server consumer flag, or the mandatory legacy root path.

The test skips explicitly when either the PostgreSQL URL or external Iggy
address is absent. A skip does not create the evidence artifact and is not a
successful runtime claim.

## Deliberate boundary

D5 does not execute the server-owned worker loop or retry backoff. It does not
inject DLQ publication failure, publish-mark ambiguity, poison identity
collision, projector execution, owner-checkpoint advancement, missing-delivery
repair, multi-process locking, deletion/ACL ordering, Search-disabled recovery,
or `LINK-FORUM-03` completion.

Those remain separate bounded runtime slices under the parent D0 protocol.
