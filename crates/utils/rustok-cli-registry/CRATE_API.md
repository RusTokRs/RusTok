# `rustok-cli-registry` Crate API & Architecture Contract

## 1. Architectural Purpose & Boundaries

`rustok-cli-registry` provides the centralized registry and distribution aggregator for RusToK CLI command providers. It connects modular, owner-defined command extensions across domain crates (such as `rustok-auth-cli`, `rustok-blog-cli`, `rustok-media-cli`, `rustok-modules-cli`, `rustok-profiles-cli`, `rustok-rbac-cli`, `rustok-installer-cli`, and `rustok-social-graph-cli`) to the central platform CLI runner (`rustok-cli`) through code-generated provider factory bindings.

Key responsibilities:
- Aggregates boxed command provider instances (`SelectedDistributionRegistry`).
- Constructs the full distribution registry from active runtime composition (`selected_distribution_registry`).
- Gathers and deterministically sorts all registered command descriptors by namespace and name (`commands`).
- Decouples individual module CLI extensions from monolithic runner dependencies.

## 2. Selected Distribution Registry Model

`SelectedDistributionRegistry`:
- `empty()`: Creates an empty distribution registry.
- `from_providers(Vec<Box<dyn CommandProvider>>)`: Constructs a registry from an explicit vector of boxed providers.
- `providers(&self) -> Vec<&dyn CommandProvider>`: Borrows provider trait object references for dispatch.
- `len(&self) -> usize`: Returns the count of registered providers.
- `is_empty(&self) -> bool`: Checks if any providers are configured.

## 3. Lexicographical Sorting & Deterministic Inventory

- `commands(&self) -> Vec<CommandDescriptor>`:
  Flattens command descriptors from all registered providers and sorts them lexicographically by `namespace`, breaking ties by `name`. This ensures stable terminal listings and reproducible JSON output across test runs and environments.

## 4. Code-Generated Provider Composition

- `generated::generated_providers(&RuntimeComposition)`:
  Code-generated by `scripts/generate/generate-cli-registry.mjs`. Automatically instantiates provider entrypoints for all enrolled module CLI extensions matching the active distribution build.

## 5. Universal Logic Dimensions Verification

1. **Preconditions & Bounds**:
   - Empty registries operate safely without allocating or panicking.
   - Provider count queries reflect actual registered collection length.
2. **Branch Completeness & Anti-Swallowing**:
   - Provider instantiation passes through the shared `RuntimeComposition` ensuring consistent configuration across all subsystems.
3. **State Transition Integrity**:
   - Registry instances are immutable once constructed from provider vectors.
4. **Side-Effect Completeness**:
   - Command collection is purely in-memory and side-effect free.
5. **Algorithmic Correctness**:
   - Guaranteed total ordering of command descriptors (`namespace` primary, `name` secondary).
6. **Order of Operations & Concurrency**:
   - `CommandProvider` requires `Send + Sync`; provider references can be safely shared across concurrent execution tasks.
