## Что исправлено по компонентам

### Парсер (`lib/src/parser/ftl_parser.dart`)

1. **Табы — это контент, а не разметка.** `blank_inline ::= "\u0020"+` и
   `blank_block ::= (blank_inline? line_end)+`, поэтому таб больше нигде не
   считается отступом/разделителем:
   * `key = \tValue` → значение `"\tValue"` (как в фикстуре `tab.ftl`);
   * `key\t= value` и отступ табом → junk;
   * `_continuationAt`, `_attributeDotIndex`, `_skipBlankLines`,
     `_skipInlineWhitespace`, `_skipWhitespace` работают только с пробелами и
     переводами строк (`blank` = пробелы + `line_end`).
2. **Правый край значения обрезается.** Последний текстовый элемент паттерна
   проходит `rstrip(" \n\r")` (этап `dedent` в референсе) и удаляется, если
   пуст. Таб при этом сохраняется (фикстуры `key05 = \t`, `key06 = \t\t`).
   Для ресурсов репозитория это убирает лишние пробелы, например
   `product-list-imageAlt = Product image: `.
3. **Строгая обработка значений.** Терм без значения, атрибут без значения и
   вариант без значения теперь junk (`Term ::= ... Pattern`, `Attribute ::= ...
   Pattern`, `Variant ::= ... Pattern`); `FtlTerm.value` и `FtlAttribute.value`
   и так не-nullable, пустой паттерн был потерей данных.
4. **Ключи вариантов** валидируются как `Identifier` или `NumberLiteral`
   (`VariantKey ::= "[" blank? (NumberLiteral | Identifier) blank? "]"`).
5. **`}` — всегда ошибка внутри паттерна** (`}` в тексте запрещён,
   `text_char ::= any_char - "{" - "}" - line_end`), включая значения вариантов;
   строка-закрывашка селекта распознаётся через правило начала строки.
6. **Правило продолжения строки** приведено к `is_value_continuation`:
   `{` в начале строки продолжает паттерн на любой колонке (block placeable),
   `}`, `.`, `[`, `*` всегда завершают паттерн, прочие символы продолжают
   только при отступе. Ранее отступленный `}` мог попасть в значение, а
   отступленные `[`/`*` внутри значения не завершали паттерн.
7. **Правила каллеров (E0016–E0019)**: ссылка на сообщение не может быть
   селектором (`{ message -> }`), значение терма не может быть селектором
   (`{ -term -> }`), атрибут терма не может быть значением placeable
   (`{ -term.attr }`), но остаётся допустимым селектором
   (`{ -term.attr -> }`) — как в фикстуре `callee_expressions`.
8. **Записи начинаются с колонки 0**, блок комментариев требует пробел после
   маркера, сохраняет уровень (`#`, `##`, `###`) и прерывается при смене уровня;
   уровень блока теперь доступен в AST (`FtlComment.level`, 0/1/2 — A-21).
9. **Атрибуты после пустых строк** разрешены (`Attribute ::= line_end blank?
   "." ...`, где `blank` включает `line_end`), отступленные `.attr`
   распознаются только с пробелами.
10. **Вызовы функций/термов** допускают `blank?` перед `(` (`CallArguments ::=
    blank? "(" ...`), но пробелы не потребляются, если вызова нет, чтобы
    `{ msg\n.attr }` остался ошибкой.
11. **Составные определения** значений `NUMBER()`/вариантов сверены с
    фикстурами `multiline_values` (`key05`–`key13`) и `whitespace_in_value`
    (пустые и «пробельные» строки схлопываются в `\n`).

### Резолвер (`lib/src/resolver/fluent_resolver.dart`)

* Ссылка на сообщение резолвится **в области вызывающего** (`args` наследуются),
  терм — в собственной области (в референсе `resolveTermReference` сбрасывает
  scope). Ранее `{ greeting }` терял переменные вызывающего.
* BiDi-изоляция (`FSI`/`PDI`) применяется только если в паттерне больше одного
  элемента и placeable не является строковым/числовым литералом — в точности как
  `FluentBundle._useIsolating && ptn.length > 1` в fluent.js и как
  `compile_Pattern`/`NeverIsolatingPlaceable` в python-fluent. Раньше изолировался
  в том числе одиночный `{ $name }`, что давало лишние управляющие символы.
* `NUMBER()`: целые значения форматируются через `toString()` (полная точность
  выше 2^53) с добавлением нулей при `minimumFractionDigits`, а при
  экспоненциальной форме `toStringAsFixed` (от `1e21`) значение выводится без
  недопустимой группировки.

### Плюрализация (`lib/src/resolver/cldr_plurals.dart`)

Файл перегенерирован из данных CLDR 48: таблица строится из
`cldr-core@48.2.0/supplemental/plurals.json` — по одному `case`-блоку на каждую
из 40 встречающихся форм правил (223 языковых тега, включая отдельное правило
`pt-PT`). Правила CLDR переписаны в условия Dart: `n` — модуль значения, `i` —
целая часть, `v` — число видимых дробных цифр, `f` — их значение; `t` из CLDR
отображён в `f`, `w` в `v` (кратчайшая десятичная запись `num` не оканчивается
на ноль, поэтому операнды совпадают), а компактный показатель `e` свёрнут в `0`,
так как пакет не форматирует числа в компактной нотации. Диапазоны CLDR
(`n % 100 = 3..10`) реализованы хелпером `_inRange`, который истинен только для
целых значений из диапазона — как сравнение с множеством целых в CLDR.

Что изменилось относительно прежней рукописной версии:

| Языки | Что было | Что стало |
|---|---|---|
| 88 языков (`af`, `bg`, `el`, `hu`, `tr`, `uz`, …) | английское правило | `one: n = 1`, включая дроби с кратчайшей формой `1` |
| 12 языков (`hi`, `bn`, `fa`, `gu`, `kn`, `kok`, `pcm`, `zu`, …) | английское правило | `one: i = 0 or n = 1` (`0`, `1`, `0.5`, `0.04` → `one`) |
| 10 языков (`ak`, `mg`, `pa`, `ti`, …) | английское правило | `one: n = 0..1` |
| 9 языков (`iu`, `naq`, `se`, …) | английское правило | `one: n = 1`, `two: n = 2` |
| `cy`, `ga`, `gd`, `gv`, `kw`, `mt`, `br`, `shi`, `tzm`, `lag`, `is`, `da`, `sgs`, `si` | английское правило | полные правила CLDR (`zero`…`many`, диапазоны, `t`/`f`) |
| `fil`/`tl`/`ceb`, `dsb`/`hsb`, `ff`/`hy`/`kab`, `blo`/`cv`/`ksh` | английское правило | собственные правила CLDR |
| `ca`, `it`, `scn`, `vec`, `lld`, `pt-PT`, `es`, `pt` | часть была без `many` | `many` для точных миллионов (`e = 0 and i % 1000000 = 0 and v = 0`) |
| `pl` | дроби → `many` | дроби → `other` (все клаузы требуют `v = 0`) |
| `lv` | любые дроби → `other` | `v = 2` и `f % 100 = 11..19` → `zero`; `f % 10 = 1` → `one` |
| `ar` | любые дроби → `other` | `0.0` → `zero`, `1.0` → `one`, `2.0` → `two` |
| `ro` | `101`, `1001` → `other` | `101`, `1001` → `few` (`n % 100 = 1..19`) |
| `sr`/`hr`/`bs`/`mk` | `mk` отсутствовал | клаузы по `f` (`f % 10 = 1` → `one`, `2..4` → `few`) |

Ограничения зафиксированы в doc-комментарии: `NaN` и бесконечности → `other`;
невидимый конечный ноль (`1.0` — это `1`) и экспоненциальная запись считаются
без видимых дробных цифр; теги, для которых CLDR не публикует правило, дают
`other`.

Проверка: все `@integer`/`@decimal`-примеры из `plurals.json`, представимые
типом `num` (3420 значений; 2517 примеров вида `1.0` пропущены как
непредставимые), прогнаны через мини-интерпретатор сгенерированных условий —
0 расхождений; отдельно сверены все 51 числовое ожидание из
`test/rustok_i18n_test.dart`.

### Accept-Language (`lib/src/accept_language/accept_language_parser.dart`)

* Индекс появления диапазона фиксируется до валидации, поэтому при равных `q`
  сохраняется исходный порядок заголовка (раньше счётчик учитывал только
  принятые диапазоны).
* `q` разбирается строго, как `rustok-ui-i18n::parse_quality`: `0`, `1`,
  `0.<1..3 цифры>`, `1.000`; `NaN`, `.5`, `1.001`, `0.1234`, дублированный `q`
  и «голый» `q` приводят к пропуску диапазона, а не к порче последующих.
* `q=0` — диапазон явно неприемлем и пропускается.

### `rustok_flutter_i18n`

Дефектов в коде виджетов и провайдеров не найдено: `FluentScope` передаёт
`revision` при появлении сообщений, `DirectionalityHandler` берёт направление из
активного локаля, `localeReadyProvider` грузит `LazyCatalog` по цепочке
fallback, `setLocale` нормализует тег и бросает `ArgumentError` на мусор.
Закрыты пробелы документации: поведение при ошибке загрузки, dotted-ключи для
атрибутов и расширения, требующие `FluentScope` (A-17).

### CLI (`lib/src/cli/i18n_cli.dart`)

Контракт ключей и атрибутов теперь читается напрямую из AST парсера
(`_SourceContract`), а не через повторные обращения к бандлу: это делает
сравнение атрибутов явным и симметричным. Добавлена проверка **лишних**
атрибутов — раньше сообщение с атрибутом, которого нет в базовой локали,
проходило проверку молча (A-18). Дублирующий разбор источника сохранён: бандл
нужен для диагностики (junk, дубликаты ID), AST — для контракта.

## Проверено, отклонений не найдено

* Многострочные значения и общий отступ: фикстуры `multiline_values`
  (`key01`–`key13`), `blank_lines`, `leading_empty_lines_with_ws`,
  `whitespace_in_value` — поведение совпадает с эталоном.
* `FtlResource` (first-wins по ID + junk) и `FluentBundle` (диагностика,
  `format(id, args, attribute)`, защита от циклов `_maxDepth = 100`).
* Экранирование строк: только `\\`, `\"`, `\uXXXX`, `\UXXXXXX` (E0025/E0026).
* Числовые литералы допускают ведущие нули (`digits ::= [0-9]+`), `-` и дробную
  часть — как в EBNF.
* `LocaleTag`: лимит 64, POSIX-суффиксы (`.UTF-8`, `@euro`), legacy-алиасы
  `in`/`iw`/`ji`, варианты `5..8` символов и `[0-9][a-z0-9]{3}`, участие
  расширений в `==` (исключение из `hashCode` — корректно для Dart).
  Grandfathered-теги (`en-GB-oed`, `i-klingon`) отклоняются, как в ICU4X.
* CLI: `check` сравнивает ключи и атрибуты в обе стороны и печатает
  диагностику парсера; `typegen` проверяет имя класса, коллизии членов и
  параметров.
* Ресурсы: во всех 120 `.ftl` нет табов и конструкций, которые новые
  строгие правила объявили бы junk.

## Известные ограничения (сознательно не менялись)

* Вложенный placeable (`{ { $x } }`, `{ FUNC({ $x }) }`) — валиден по EBNF, но
  AST не содержит узла placeable-выражения; это описано в разделе ограничений
  README (в ресурсах репозитория не используется).
* `NUMBER()`/`DATETIME()` реализуют подмножество опций Fluent/`Intl`
  (без `unit`, significant digits, `era`, `dayPeriod`, `timeZoneName` и
  не-Gregorian календарей) — как и заявлено в README.
* Числовая защита селектора: если селектор — `NUMBER(...)`, а ключ варианта —
  число, категория выбирается по исходному числу, но точное сравнение с ключом
  идёт по строке результата; строковые селекторы, где число записано с
  разделителями групп (`"1,234"`), остаются числовыми из соображений
  практичности.
* Приложения `rustok_mobile/apps/*` пока не подключают пакеты (Phase 6 плана) —
  интеграция вне рамок этой ревизии.

## Раунд 2: конформанс с эталонными реализациями

Второй проход был посвящён не столько отдельным багам, сколько проверяемости:
парсер сверен с эталонами правило за правилом (включая случаи, где эталоны
расходятся между собой) и снабжён исполняемым конформанс-набором.

### Как проверялось

* **Двойник парсера.** `lib/src/parser/ftl_parser.dart` построчно перенесён в
  Python (`/tmp/twin.py`, ~1030 строк: AST, семантика `StringBuffer`,
  метод-в-метод), чтобы исполнять алгоритм там, где нет Dart SDK.
* **Корпус из 254 источников** (`/tmp/expected.json`): 34 файла
  `fixtures_reference` плюс 220 курируемых фрагментов. Ожидания получены
  **запуском** `@fluent/syntax@0.19.0` (`oracle.js`), а не переписыванием
  JSON-фикстур, — так проверяются в том числе junk-границы.
* **Дифференциальный фаззер** (`/tmp/fuzz.py`): 10 000 мутированных источников
  сверены с живой реализацией `python-fluent` (`fluent.syntax`); расхождений 0.
* **Арбитр при расхождениях эталонов** — EBNF спецификации
  (`projectfluent/fluent/spec/fluent.ebnf`), а не «среднее» между реализациями.
* Итог двойника: **254/254** кейса корпуса совпадают с эталоном
  (`python3 /tmp/twin.py /tmp/expected.json` → `254 cases, 0 mismatching`).
* В репозиторий добавлены `test/fluent_conformance_test.dart` (254 кейса) и
  `test/data/ftl_reference_corpus.json` (тот же корпус в языке-нейтральном виде).

### Расхождения эталонов и принятые решения

| Правило | `python-fluent` | `@fluent/syntax` 0.19 и `fluent-syntax` | Решение |
|---|---|---|---|
| Конец junk | строка `//` или `[[` тоже завершает junk (совместимость с Syntax 0.4) | только строка, начинающаяся с буквы, `-` или `#` | **EBNF + JS/Rust**: `//` и `[[` остаются внутри junk |
| Вариант `[[key]]` | не начинает вариант (Syntax 0.4) | начинает → ошибка ключа | **JS/Rust**: это ошибка ключа |
| Перемотка при ошибке | не возвращается на строку с ошибкой | откатывается к концу предыдущей строки | **JS/Rust**: junk заканчивается перед строкой, начинающей запись |
| Комментарий в конце файла (`#` без пробела и перевода строки) | junk | junk | **junk** (было: валидный комментарий) |
| `\U` вне диапазона | `ValueError` | необработанный `RangeError` (падение) | **Dart-реализация**: junk + диагностика |
| Вложенный placeable (`{ { $x } }`, аргумент вызова) | поддержан | поддержан | **поддержан** (было: junk) |
| Комментарий-переводчик (`# ...` над записью) | приклеивается к сообщению/терму | так же | **реализовано** |

## Раунд 3: числа, проценты и валюта по CLDR

Третий проход закрыл самый большой пробел библиотеки: локальные данные

вся числовая часть идёт из CLDR 48 (пакеты `cldr-numbers-full@48.2.0` и

### Как проверялось

* **Числа и проценты.** `Intl.NumberFormat` (Node, ICU) сверен с таблицей по

    (буквенный код отделяется NBSP, знак валюты — нет): CLDR пишет чужую

* `fr-CH` расходится с Node-реализацией из-за версии данных ICU, а не логики:
  CLDR 46+ использует апостроф, ICU в песочнице — узкий NBSP.
* `en-*`-регионы Европы и `de-AT`/`de-LI`: ICU/V8 игнорирует региональный
  валютный паттерн. Пакет следует CLDR (как `package:intl`), поэтому в этих
  локалях вывод осознанно отличается от Node (в Flutter-приложении эталон —
  Dart-`intl`, а не V8).
* Тест-файлы `test/number_format_test.dart` и `test/currency_format_test.dart`
  покрывают те локали, где ICU и CLDR согласны; теги с устаревшими данными ICU
  (`fr-CH`) в них сознательно отсутствуют — они описаны в отчёте.

## Раунд 4: остаток генератора типов и сырые junk-ассерты

Четвёртый раунд закрывает два хвоста, зафиксированных как непокрытые в раундах
2–3: (а) остаток `typegen` — кодогенератор до этого сверялся только с
собственными тестами и никогда не компилировался, а его правила именования и
набора параметров не сверялись с семантикой резолвера; (б) рукописные ассерты
границ junk в `test/rustok_i18n_test.dart`, зависящие от инклюзивной перемотки.

### Как проверялось

* Кодогенератор (`lib/src/cli/i18n_cli.dart`) прочитан построчно против
  резолвера (`lib/src/resolver/fluent_resolver.dart`): какие переменные
  резолвер читает из области вызывающего, те и обязаны быть параметрами
  сгенерированного метода. Проверены все ветки `_collectExpressionVariables`
  против `resolveExpression`/`_resolveMessage`/`_resolveTerm`.
* Составлены входные `.ftl`, которые дают каждый опасный случай, и для них
  вручную выведен ожидаемый текст генерации (в том числе побайтово — см.
  golden-тест).
* Таблица плюрализации и данные числа/валюты сверены с `cldr-core@48.2.0`
  (`plurals.json`) и `cldr-numbers-full@48.2.0` заново скачанными из npm,
  генераторы прогнаны повторно и сравнены по md5 с закоммиченными файлами.
* Junk-ассерты разобраны пошагово: для каждого входа вручную вычислены
  `entryStart`, позиция ошибки, результат `input.lastIndexOf('\n', errorPos)` и
  границы, которые даёт `_nextEntryStart` (инклюзивный поиск, как в
  `@fluent/syntax`). Все ассерты согласованы с текущей реализацией; изменить
  ничего не потребовалось (см. ниже).

### Что исправлено

| # | Находка | Компонент | Исправление |
| :--- | :--- | :--- | :--- |
| D-01 | Параметры метода не покрывали переменные сообщений, на которые он ссылается: резолвер наследует переменные вызывающего (A-01), поэтому `wrapped = { greeting }` при `greeting = Hello { $name }` рендерился без `name`, а передать его сгенерированный геттер не позволял | `i18n_cli` | Генератор обходит ссылки на сообщения (транзитивно, с защитой от циклов) и добавляет их переменные в сигнатуру; термы не обходятся — у них своя область, как и в резолвере |
| D-02 | Ключ `locale` давал член `locale` рядом с полем `final String? locale;` — дублирующий член, то есть невалидный Dart | `i18n_cli` | Зарезервированные имена членов (`locale`, `toString`, `hashCode`, `runtimeType`, `noSuchMethod`) получают суффикс `Message`: `locale` → `localeMessage` |
| D-03 | Ключи и атрибуты, отображающиеся в члены `Object` (`to-string`, `hash-code`, `runtime-type`, `no-such-method`; атрибут `.string` у сообщения `to` → `toString`), давали геттеры с несовместимым переопределением | `i18n_cli` | Тот же `_reserveMemberName` применяется и к именам атрибутов: `toString` → `toStringMessage`, `to.string` → `toStringMessage` |
| D-04 | Переменная `$locale` давала параметр `locale`, который затенял поле: тело `locale: locale` передавало в `t()` аргумент сообщения вместо локали экземпляра — сообщение рендерилось не для запрошенной локали | `i18n_cli` | Зарезервированные имена параметров: `locale` → `localeArg`; в теле `locale: locale` теперь всегда поле |
| D-05 | `--className UiMessages` принимался: сгенерированный класс затенял тип каталога, на который ссылается собственное поле `_messages` (невалидный Dart) | `i18n_cli` | Имя класса проверяется по списку типов, которые использует сгенерированный файл; `UiMessages` отклоняется с сообщением |
| D-06 | Строка итога утверждала «attribute-only messages are skipped», хотя сообщение без значения не пропускается, а даёт геттеры атрибутов; комментарий `_SourceContract` утверждал, что `FluentBundle` не выражает такие сообщения | `i18n_cli` | Формулировка заменена на «accessors: N, keys: M; a message without a value contributes attribute getters only»; устаревший комментарий переписан |
| D-07 | Устаревшие числа в документации: 738/126 кейсов вместо 998/291, «ключи ≤ 128 байт» вместо 256, «223 языковых тега» плюрализации | README, CHANGELOG | Все три числа исправлены; для плюрализации указано точное состояние CLDR 48: 224 тега, 223 правила (`kok-Latn` делит правило `kok`, `pt-PT` — собственное) |
| D-08 | Сгенерированный код никогда не компилировался в CI: `typegen` писал в `/tmp`, а `dart analyze` выполнялся раньше | workflow | `typegen` пишет в `example/generated/` (покрыт существующим правилом `.gitignore` `**/generated/`) до `dart analyze`, поэтому сгенерированный файл компилируется в CI; добавлен job `tooling` (Python-контракты и node-симуляция), не требующий Dart SDK |

### Junk-ассерты: проверка без изменений

Разобраны 14 кейсов группы «Fluent 1.0 conformance» в
`test/rustok_i18n_test.dart` (значения junk, термины/атрибуты без значения,
вариант без значения и с неверным ключом, `}` в варианте, пустые строки перед
атрибутами, схлопывание пустых строк внутри значения, уровни комментариев и
пробел после маркера, правила каллеров, ссылка-селектор, `//`/`[[` в junk,
граница junk перед новой записью). Для каждого входа пересчитаны границы junk
по `_nextEntryStart` с инклюзивным `lastIndexOf`: ожидаемые количества и тексты
совпадают с реализацией, правок не требуется.

Ключевой кейс, закрепляющий инклюзивную перемотку: `key = {\nother = $value\n
next = 1\n` → junk ровно `key = {\n` (одна строка). При исключительном поиске
(`rfind('\n', 0, error_pos)` из `python-fluent`) junk поглотил бы и строку
`other = $value`, то есть тест прямо фиксирует выбранную семантику JS/Rust.

### Остаточные ограничения раунда 4

* В песочнице нет Dart/Flutter SDK, поэтому сгенерированный код и новые тесты
  по-прежнему не компилировались здесь: golden-тест, тесты ре-наименований и
  пример из `example/generated/` проверяются `dart analyze`/`dart test` (в CI
  они исполняются; локальный вывод — см. команды ниже).
* Прогоны раундов 2–3 (двойник `twin.py`, фаззер, `numprobe`) выполнялись во
  временной лаборатории `/tmp`, которая не сохраняется вместе с репозиторием:
  их результаты остаются в отчёте как исторические, а воспроизводимые сейчас
  проверки — конформанс-набор в `test/fluent_conformance_test.dart`,
  сгенерированные тесты чисел/валют и скрипты в `rustok_mobile/tooling`.
* Компилятор `typegen` не умеет `--dir`/несколько входных файлов: класс
  строится из одного `.ftl`, как и было; это осознанное ограничение CLI.
