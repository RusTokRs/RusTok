# Расширение Rust anti-slop / logic-hygiene стандарта RusTok для Doctor

## Исходный стандарт, границы исследования и обнаруженные пробелы

На дату исследования, **27 ноября 2026 года**, `docs/standards/logic-hygiene-patterns.md` — активный канонический стандарт RusTok для `domain-logic-patterns` и `anti-slop-remediation`. В самом документе уже зафиксировано принципиально важное разграничение: таблица `Confirmed cases in RusToK` содержит подтверждённые исторические дефекты, тогда как остальные записи являются review-guidance до проверки конкретного owner path и его поведения; Doctor findings также должны разделять потенциальный impact и confidence. Это разграничение следует сохранить буквально: ни один из предлагаемых ниже `P-RUST-*` не является автоматически «найденным багом RusTok». citeturn500845view0

Нынешний Doctor сознательно работает как **лексический сканер**: сохраняет литералы и локальный scope, но не разрешает Rust-типы, не раскрывает макросы и не идёт по call graph. Его `strict`-режим блокирует только high-confidence findings соответствующей severity, а пустой результат прямо не считается доказательством соблюдения поведенческих инвариантов. Поэтому значительная часть действительно ценных Rust-проверок не должна искусственно втискиваться в regexp-ядро: нужен второй типизированный/HIR-backed producer и отдельный класс contract/data-flow findings. citeturn854684view1

Большая часть очевидных анти-паттернов уже присутствует и **не должна дублироваться** новыми `P-RUST-*`: в матрице есть `P-ZERO-PANIC-PROD`, `P-SYNC-LOCK-AWAIT`, `P-BLOCKING-IO-IN-ASYNC`, `P-JSON-DECODE-DEFAULT`, `P-FILTER-DROPPED-ERROR`, `P-ORPHAN-SPAWN`, `P-UNBOUNDED-ALLOC-OOM`, `P-ATOMIC-BACKPRESSURE`, `P-TXN-ROLLBACK-SWALLOW`, `P-SILENT-EVENT-DISCARD`, `P-LOSSY-JSON-NUMBER`, `P-DEV-DEP-PROD-LEAK`, `P-STALE-ALLOW-LINT`, `P-TLS-DANGER-BYPASS` и ряд других. Например, `P-ORPHAN-SPAWN` уже проверяет не привязанные к supervisor `tokio::spawn`, а `P-JSON-DECODE-DEFAULT` отдельно описывает превращение ошибки `serde_json` в успешный default. citeturn854684view0turn854684view2

Текущий корневой `Cargo.toml` RusTok уже заявляет `edition = "2024"` и `rust-version = "1.96"`, при этом virtual workspace явно оставляет `resolver = "2"`. Это **наблюдаемый факт конфигурации, а не доказанный дефект**: Cargo разрешает явно выбирать resolver; Edition Guide лишь указывает, что Rust 2024 по умолчанию соответствует resolver 3, а для virtual workspace resolver всё равно задаётся явно. Поэтому Doctor вправе выдавать лишь informational/intent finding вроде «2024 workspace intentionally retains resolver 2?» — но не P1/P0. citeturn500845view1turn350218search3turn350218search4

Актуальный stable Rust на дату исследования — **Rust 1.100.0**, выпущенный 12 ноября 2026 года. Он, в частности, добавил Cargo lint для unused dependencies и стабилизировал `global-min-publish-age`, то есть dependency cooldowns. Последние уменьшают окно некоторых supply-chain атак, но сами Rust/Cargo подчёркивают, что это не полноценная защита и не заменяет review зависимостей. citeturn885618search0turn885618search1

Из структуры существующего стандарта следует полезная архитектурная граница. Новый каталог стоит поделить на три уровня обнаружения: **L0 lexical** — то, что нынешний Doctor способен делать без типов; **L1 typed/HIR** — rustc/Clippy/rust-analyzer producer с реальными типами и trait resolution; **L2 contract/data-flow** — межпроцедурные или owner-aware проверки, которые никогда не следует объявлять high confidence только на основании regex. Такое разделение непосредственно следует из текущих ограничений Doctor и позволит уменьшить нынешнюю проблему, когда хороший Rust smell невозможно надёжно отличить от разрешённого паттерна без типа или контракта. citeturn854684view1

## Кандидаты высокой ценности: async, ownership и concurrency

**`P-RUST-LET-UNDERSCORE-FUTURE` — Future создан и сразу уничтожен.** Категория: async lifecycle; dimensions: side-effect completeness, branch completeness, execution semantics. Антипример: `let _ = send_email(...);` или `_ = service.run();`, когда выражение имеет тип `Future`: future никогда не poll'ится, поэтому ожидаемая асинхронная работа не происходит. Допустимо только если создание future само по себе и есть намеренный эффект, что для Rust async API нетипично и должно быть явно документировано. Исправление: `.await?`, `spawn` с supervision либо явный `drop(future)` с пояснением. Быстрый детектор: Clippy `let_underscore_future`; L1 HIR pattern `Stmt::Local(PatKind::Wild, init)` + `Future` type; L0 regex `let\s+_\s*=\s*[\w:.]+\([^;]*\);` только для allow-listed async API и только heuristic. Severity `P1`, confidence `high` при HIR/Clippy, `heuristic` при lexical. Regression: fixture, где future устанавливает observable flag; negative fixture с явным `drop`. Clippy специально описывает этот случай как обычно пропущенный `.await`; это первичный semantic evidence. citeturn984086search10

**`P-RUST-LET-UNDERSCORE-LOCK` — lock guard немедленно уничтожен.** Категория: synchronization/lifetime; dimensions: order/concurrency, critical-section integrity. `let _ = mutex.lock().unwrap(); work();` не удерживает блокировку во время `work()`: wildcard binding дропает guard немедленно. Rustc имеет deny-by-default `let_underscore_lock`; если намерение действительно «acquire-and-immediately-release», `drop(lock.lock()?)` выражает его явно. Detector: rustc lint как authoritative L1; L0 можно искать `let _ = .*\.lock\(`, но high confidence должен приходить от rustc, поскольку тип `lock()` важен. Severity `P1`, confidence `high`; FP почти отсутствуют после type resolution. Regression: две конкурентные задачи должны доказать, что критическая секция фактически сериализована. citeturn984086search2turn984086search1

**`P-RUST-AWAIT-HOLDING-REFCELL` — динамический borrow живёт через `.await`.** Категория: ownership/async state; dimensions: concurrency, failure paths. `RefCell::borrow()`/`borrow_mut()` через suspension может привести к runtime borrow panic при re-entry или иной ветке, хотя borrow checker это разрешает. Canonical fix: сузить lexical block и получить owned/копируемое значение до `.await`, либо сменить модель владения. Detector: Clippy `await_holding_refcell_ref`; HIR проверяет live `Ref`/`RefMut` across yield. Severity `P1`, confidence `high` при точном live-range; lexical imitation не нужна. Известное ограничение родственных Clippy-проверок — явный `drop()` может давать неудобные результаты анализа; блок scope надёжнее и для кода, и для анализа. citeturn984086search10

**`P-RUST-SELECT-CANCEL-UNSAFE` — cancellation-unsafe operation внутри повторяющегося `tokio::select!`.** Категория: cancellation/progress; dimensions: concurrency, branch completeness, fairness. Tokio прямо определяет cancellation safety как свойство, при котором drop незавершённого future и последующее создание нового не теряет прогресс. `Mutex::lock`, `RwLock::{read,write}`, `Semaphore::acquire` и `Notify::notified` теряют место в fair queue при cancellation; `read_exact`, `read_to_end`, `write_all` также не cancel-safe и могут потерять частичный прогресс. Это не означает, что любое применение в `select!` ошибочно: one-shot shutdown select может сознательно отбросить работу. Наиболее ценный Doctor detector: AST/HIR `loop|while { tokio::select! { ... } }` + resolved callee из denylist cancel-unsafe API; повысить confidence, если future пересоздаётся на каждой итерации и competing branch продолжает loop. Fix: вынести future из цикла и pin/reuse, перестроить state machine, использовать documented cancel-safe primitive или явно признать loss semantics. Severity `P1`, confidence `heuristic`; тип анализа L1/L2. Regression: branch repeatedly wins before acquisition/completion, затем проверяется, что работа/очередь не теряется. Tokio docs дают прямой контракт по каждому перечисленному API. citeturn457832search0turn457832search3turn457832search4

**`P-RUST-SPAWN-BLOCKING-CANCEL-ILLUSION` — код считает `spawn_blocking` отменяемым.** Категория: cancellation/resource lifetime; dimensions: shutdown, side effects, boundedness. После старта `spawn_blocking` вызов `JoinHandle::abort` не останавливает closure; runtime shutdown также может ждать blocking tasks неограниченно, если используется обычное ожидание. Поэтому `timeout(handle)` или abort вокруг side-effecting blocking job не означает отмену самой операции. Fix: cooperative cancellation inside closure, конечные blocking operations, concurrency semaphore для CPU-heavy work либо отдельный управляемый worker/process. Detector L2: trace `spawn_blocking` handle → `.abort()`, `timeout(handle)`, `select!` cancellation или shutdown path; усилить finding, если closure содержит filesystem/network/database mutation или loop. Severity `P1`, confidence `heuristic`; не флагать короткие детерминированные codecs/compression только за сам `spawn_blocking`. Regression: blocking closure переживает отмену handle; owner test доказывает отсутствие side effects после cancellation contract. Tokio документирует обе особенности прямо. citeturn457832search5

**`P-RUST-UNBOUNDED-CHANNEL` — неограниченная очередь без доказанного внешнего bound.** Категория: backpressure/resource safety; dimensions: capacity bounds, admission, shutdown. Tokio `mpsc::unbounded_channel` не оказывает backpressure и может буферизовать произвольное количество сообщений до исчерпания памяти; поэтому production data plane без доказанного внешнего лимита — сильный кандидат на ошибку. Fix: bounded channel + явная политика `send().await`/`try_send`/drop/reject/overflow storage. Detector L0 high-confidence **candidate**, а не автоматический defect: `\b(unbounded_channel|unbounded)\s*::<`; контекстно снизить severity для telemetry/control-plane paths или если рядом присутствует machine-readable invariant вроде bounded producer cardinality. Severity `P1`, confidence `heuristic`; regression — нагрузить producer быстрее consumer и проверить admission limit и memory-bounded behavior. Не смешивать с существующим `P-ATOMIC-BACKPRESSURE`: тот проверяет атомарность reservation, этот — отсутствие hard capacity вообще. Tokio прямо предупреждает о неограниченном buffering. citeturn348424search4

**`P-RUST-POISON-BYPASS` — poisoned `std::sync::{Mutex,RwLock}` превращается в обычный успех.** Категория: panic safety/state integrity; dimensions: failure paths, invariant preservation. Типичный smell — `lock().unwrap_or_else(|e| e.into_inner())` или match, который без repair возвращает `PoisonError::into_inner()`. Standard library характеризует protected data после panic как потенциально tainted и подчёркивает, что poisoning лишь advisory, а не soundness mechanism. Fix: fail/restart owner, rebuild state, validate invariant before `clear_poison`, либо документированно доказать, что protected state invariant остаётся целым. Detector L0: `.unwrap_or_else(|...| ...into_inner())` и `Err(...) => ...into_inner()`; L1 подтверждает `PoisonError`. Severity `P1`, confidence `heuristic`, потому что recovery может быть сознательной. Regression: panic посреди mutation, затем recovery path обязан либо отказать, либо восстановить инвариант. citeturn457832search6turn457832search7

**`P-RUST-ARC-NONSEND-SYNC` — `Arc` используется как ложный маркер thread safety.** Категория: ownership/concurrency abstraction; dimensions: type invariants, architecture. `Arc<T>` обеспечивает атомарный refcount, но не делает внутренний `T` thread-safe; Clippy `arc_with_non_send_sync` как раз ловит `Arc<T>` для `T: !Send`/`!Sync`. Fix: `Rc` для single-thread ownership либо исправление внутренней synchronization model. Detector: Clippy producer, severity `P2` по умолчанию, повышать до `P1`, если value пересекает task/thread boundary. FP constraint: `Arc` иногда нужен только из-за API shape или будущего thread handoff; поэтому finding не должен автоматически требовать `Rc`. Rust Nomicon объясняет, почему `Rc` не `Send`, а `Arc` предназначен для атомарного shared ownership; Clippy даёт готовую типизированную сигнатуру. citeturn340052search6turn350218search0

**`P-RUST-ASYNC-MUTEX-PURE-DATA` — async mutex используется для данных, где suspension под guard не нужна.** Категория: false abstraction/complexity; dimensions: performance, ownership clarity. Tokio прямо отмечает, что async mutex дороже обычного и что для обычных данных часто предпочтителен `std::sync::Mutex`; async mutex нужен главным образом тогда, когда guard действительно должен переживать `.await`, особенно вокруг IO resource. Detector L1/L2: field имеет тип `tokio::sync::Mutex<T>`, но все `lock().await` guards lexical-live только до следующего `.await` и не защищают async IO. Severity `P2`, confidence `heuristic`; никогда не автофиксить, потому что contention, executor topology и API `Send` constraints имеют значение. Fix: owner method around `std::sync::Mutex`, message-passing owner task или оставить Tokio mutex с локальным обоснованием. Regression — contention benchmark или Loom/behavior test, а не stylistic snapshot. citeturn457832search2turn348424search10

**`P-RUST-CLONE-SNAPSHOT-DRIFT` — clone используется для обхода ownership, но меняет семантику state identity.** Категория: ownership/false abstraction; dimensions: state transitions, projection consistency. Сам по себе `.clone()` не smell. Высокоценный случай — aggregate/config/auth state клонируется до `.await`/transaction/lock, clone затем используется для решения о записи, хотя canonical instance мог измениться; другой случай — изменяется cloned value, а caller ожидает изменение оригинала. Это не должно быть lexical high-confidence rule. Detector L2: clone of nontrivial domain type → suspension/lock release → authorization/state decision или mutation; отдельный low-confidence signal — repeated `Arc::clone`/`.clone()` в hot loop уже покрывать существующим `P-HOTPATH-ALLOC`, чтобы не плодить дубли. Fix: borrow under stable snapshot boundary, immutable versioned snapshot, ID + owner reread, либо явно именовать `snapshot`. Severity `P1` только при owner/data-flow evidence, иначе `P2/manual`. Regression: concurrently mutate source after clone и доказать требуемую stale/revalidation semantics. Здесь Doctor должен выдавать «review owner contract», а не «clone запрещён».

## Кандидаты высокой ценности: IO, serialization, secrets, unsafe и FFI

**`P-RUST-UNUSED-IO-AMOUNT` — результат частичного `Read::read`/`Write::write` игнорируется.** Категория: IO correctness; dimensions: side-effect completeness, bounds. Один `read` или `write` не обещает обработать весь buffer; код, который игнорирует returned byte count, может тихо усечь данные. Clippy уже имеет `unused_io_amount`; типичное исправление — `read_exact`, `write_all` либо корректный loop, причём в async cancellation-sensitive state machine выбор `*_exact/*_all` должен учитывать предыдущий `P-RUST-SELECT-CANCEL-UNSAFE`. Detector L1: Clippy; severity `P1`, confidence `high`. Regression: custom reader/writer намеренно возвращает короткие chunks и проверяется полное сообщение. citeturn359460search1

**`P-RUST-SERDE-SECURITY-DEFAULT` — отсутствующее security-critical поле превращается в default.** Категория: serialization/admission; dimensions: preconditions, fail-closed behavior, compatibility. `#[serde(default)]` действительно подставляет `Default::default()` при отсутствии поля; отдельно, без `deny_unknown_fields` неизвестные JSON-поля по умолчанию игнорируются. Для DTO вроде `role`, `tenant_id`, `scope`, `algorithm`, `expiry`, `permissions`, `enabled`, `policy` это может превратить typo/старую схему в формально успешный объект. Это **не означает**, что `serde(default)` плох сам по себе: версия wire protocol, backward-compatible optional config и additive structs часто его требуют. Detector L0: parse derive attributes, security-sensitive field/name/type taxonomy, `#[serde(default)]`; отдельный advisory на strict config structs без `deny_unknown_fields`; L1 может использовать proc-macro-expanded metadata, но не обязательно. Severity `P1`, confidence `heuristic`; fix — required field, `Option` + explicit validation, versioned migration, domain newtype. Regression: missing and misspelled critical field должны fail closed. Отличается от `P-JSON-DECODE-DEFAULT`: здесь default задаётся **схемой derive**, а не post-deserialization fallback. citeturn457832search8turn457832search9

**`P-RUST-SECRET-EXFIL-TRAIT` — секрет получил обычный `Debug`/`Serialize`/logging surface.** Категория: privacy/secrets; dimensions: information flow, side effects. Для password/token/API key/secret material опасен не только прямой `println!`, уже покрываемый стандартом, но и сам тип, который автоматически `#[derive(Debug, Serialize)]`, после чего secret легко попадает в tracing, panic context, JSON или telemetry. Crate `secrecy`, уже присутствующий в workspace dependencies RusTok, специально делает access явным через `ExposeSecret`, предотвращает accidental debug leakage и не даёт `SecretBox<T>` обычный `Serialize`, пока inner type явно не помечен `SerializableSecret`. citeturn500845view1turn457832search10turn457832search11  
Doctor: L0 name-based detector `(?i)(password|passwd|secret|api_?key|access_?token|refresh_?token|private_?key)` inside a type deriving `Debug|Serialize`; L1 сильнее — type flow into tracing `%`/`?` fields, serialization, error context. Исключать hashes, token IDs, lengths и redacted wrappers. Severity `P0` для proven raw credential → log/response, `P1 heuristic` для suspicious derives. Fix — secret newtype/`SecretBox`, redacted `Debug`, explicit exposure at minimal boundary. Regression: formatted/logged wrapper никогда не содержит sentinel secret, serialization без explicit owner policy должна fail/не компилироваться.

**`P-RUST-UNSAFE-WITHOUT-LOCAL-PROOF` — unsafe operation не имеет локального проверяемого safety contract.** Категория: memory safety; dimensions: preconditions, bounds, aliasing. Rust Reference подчёркивает: `unsafe` не ослабляет запрет UB; safe API вокруг unsafe обязан быть sound для любого safe caller. В Rust 2024 `unsafe_op_in_unsafe_fn` уже warn-by-default: даже внутри `unsafe fn` небезопасная операция должна находиться в явном `unsafe {}`. Clippy также имеет `undocumented_unsafe_blocks`, а `multiple_unsafe_ops_per_block` полезен для уменьшения proof surface. citeturn975785search2turn975785search3turn350218search0turn350218search1  
Предлагаемая Doctor-сигнатура: L0 `unsafe {`/`unsafe fn` без ближайшего `// SAFETY:` либо `/// # Safety`; L1 объединить с `unsafe_op_in_unsafe_fn`, `undocumented_unsafe_blocks`, `unused_unsafe`. **Комментарий не доказывает soundness**, поэтому максимум `P1/high` означает «нарушена policy of local proof», а не «найден UB». Для unsafe, закрывающего raw pointer/FFI/aliasing, добавить required evidence field `miri|compile_fail|owner_test`. Regression: unsafe fixture с documented preconditions + negative compile/test. Miri затем используется как динамическое доказательство конкретных executions, но его чистый прогон не доказывает soundness. citeturn885618search3

**`P-RUST-STATIC-MUT-REFERENCE` — reference на `static mut`.** Категория: memory safety/global state; dimensions: aliasing, concurrency. Rust 2024 делает `static_mut_refs` deny-by-default: уже само создание ссылки может нарушить aliasing, а корректность требует глобального reasoning через threads/reentrancy. Fix: immutable `static` + locally-reasoned interior mutability, lock/atomic/OnceLock либо, если FFI действительно требует raw pointer, `&raw const`/`&raw mut` с минимальным unsafe scope. Detector: rustc lint — готовый automatic rule; lexical scanner может лишь дополнительно inventory `static mut`. Severity `P0`, confidence `high` от rustc. Regression: compile-fail lint fixture и Miri для wrapper logic, где применимо. citeturn350218search6

**`P-RUST-FFI-CONTRACT-UNVERIFIED` — extern declaration считается безопасным только потому, что компилируется.** Категория: FFI/memory safety; dimensions: preconditions, ownership, ABI, unwind. В Rust 2024 `extern` blocks обязаны быть `unsafe`, но Edition Guide подчёркивает: автоматическая миграция **не проверяет правильность сигнатур**; неверный ABI/signature способен вызвать UB. Reference отдельно перечисляет вызов функции с неправильным ABI и unwinding через несовместимую границу среди UB. citeturn350218search7turn975785search2  
Doctor L0 может inventory `unsafe extern`, `extern "C" fn`, `#[unsafe(no_mangle)]`, raw pointer + length pairs. L2 finding повышается, если safe exported/imported wrapper принимает raw pointer без null/alignment/len/ownership validation или FFI callback допускает panic через `"C"`. Severity `P0` при доказанном unsafe safe-wrapper contract violation; иначе `P1/manual`. Fix: tiny unsafe boundary, explicit `# Safety`, checked slice construction, ABI ownership docs, panic boundary strategy. Regression: boundary tests для null/zero/oversized len, ABI smoke test, sanitizers/Miri там, где FFI emulation возможна; Miri сам предупреждает, что большинство FFI/platform APIs он не поддерживает. citeturn885618search3

**`P-RUST-MEM-FORGET-RESOURCE` — `mem::forget` применяется к RAII resource без явного transfer contract.** Категория: resource lifetime; dimensions: side-effect completeness, leak safety. `std::mem::forget` безопасен в memory-safety смысле, но обход `Drop` для file/socket/guard/tempdir/secret/resource handle часто означает leak или незавершённый cleanup. Clippy `mem_forget` — restriction lint и потому не должен включаться wholesale: сами Clippy docs рекомендуют применять restriction lints индивидуально, а не как blanket policy. Detector L1: `mem::forget(x)` + type has significant `Drop`, повышать confidence для lock/file/socket/tempdir/guard; L0 только candidate. Legitimate FFI ownership transfer — явное исключение, лучше через `into_raw`/`ManuallyDrop` и contract comment. Severity `P1 heuristic`; regression — drop counter/resource closure. citeturn359460search0turn340052search5

**`P-RUST-NUMERIC-BOUNDARY-TRUNCATION` — `as`/обычная арифметика на security/resource boundary скрывает overflow или truncation.** Категория: numeric integrity; dimensions: bounds, calculation correctness. Clippy `cast_possible_truncation` находит narrowing casts и рекомендует `TryFrom` там, где потеря диапазона нежелательна; `arithmetic_side_effects` способен заставить явно выбрать checked/wrapping/saturating semantics. Эти restriction/pedantic lints слишком шумны глобально, поэтому Doctor должен ограничить их length/count/offset/TTL/quota/money/size/retry/admission полями. citeturn350218search0turn350218search1  
Detection: HIR source type wider than target + sink taxonomy (`usize`, DB integer, allocation size, TTL, pagination, content length); arithmetic result затем управляет allocation/index/timeout/auth expiry. Severity `P1 heuristic`, `P0` только если доказан memory/security sink. Fix: `try_from`, `checked_*`, explicit saturating policy. Regression: `MAX`, boundary±1 и negative-to-unsigned cases. Не дублировать `P-LOSSY-JSON-NUMBER`: этот rule касается integer/domain boundary в целом.

**`P-RUST-SYSTEMTIME-AS-DURATION` — wall clock используется как monotonic elapsed clock.** Категория: temporal correctness; dimensions: time bounds, failure semantics. `SystemTime` может идти назад, поэтому `duration_since` возвращает ошибку; `Instant` предназначен для монотонного измерения elapsed time. Особенно подозрительно сочетание `SystemTime::now().duration_since(...).unwrap_or_default()`, превращающее rollback clock в нулевую длительность и тем самым меняющее policy. Fix: `Instant` для внутренних timeout/backoff/elapsed; owner credential/application clock для persisted wall deadlines; ошибки wall clock не сворачивать в default на security path. Detector L0/L1: pair `SystemTime::now` → `duration_since`/`elapsed`, усилить при `unwrap_or_default`; severity `P1 heuristic`. Regression: injected clock, который движется назад. citeturn293228search7turn293228search6

## Cargo, features, API stability и supply chain

**`P-RUST-FEATURE-NONADDITIVE` — Cargo feature ведёт себя как взаимоисключающий режим и ломается при feature unification.** Категория: build/API semantics; dimensions: parity, configuration completeness. Cargo объединяет features зависимостей и прямо рекомендует проектировать features как additive. Поэтому конструкция, где `feature = "a"` отключает или семантически отменяет `"b"`, либо отдельные downstream consumers рассчитывают, что feature никогда не будет объединён с другим, опасна. citeturn350218search5turn350218search4  
Detector: manifest graph + AST `cfg(feature="x")` и `cfg(not(feature="x"))` на альтернативных реализациях одного public capability; compilation matrix `--no-default-features`, each feature, representative pairs, `--all-features`. Severity `P1 heuristic`; FP: platform/backend choices, которые намеренно mutually exclusive и имеют explicit `compile_error!` для invalid combinations. Canonical fix — additive features либо явный compile-time rejection недопустимой комбинации. Regression — matrix build/test. Это дополняет существующий `P-HOST-DELIVERY`, который уже показывает реальный класс дефектов RusTok, когда тестовый feature set отличался от host feature set. citeturn854684view2

**`P-RUST-EDITION-RESOLVER-DRIFT` — edition/workspace resolver требует явного intent.** Категория: build reproducibility; dimensions: dependency resolution. Для Rust 2024 resolver 3 является edition default и учитывает `rust-version`; но virtual workspace должен задавать resolver явно. Текущий RusTok manifest — edition 2024, resolver 2. Это не дефект само по себе, поэтому правило должно быть **P2/informational, confidence high о факте, confidence none о вреде**: «2024 virtual workspace explicitly remains on resolver 2; attach rationale or upgrade». citeturn500845view1turn350218search3  
Detector — чистый TOML AST. Regression — manifest fixture. Такой finding полезен именно как пример того, почему Doctor обязан разделять `observation` и `defect`: факт полностью автоматизируем, намерение — нет.

**`P-RUST-BUILD-SCRIPT-TRUST-BOUNDARY` — Doctor/CI запускает Cargo на недоверенном дереве как будто это пассивный анализ.** Категория: tooling security/supply chain; dimensions: side effects, trust boundary. Cargo компилирует и **исполняет** `build.rs` перед package build; build script способен выполнять произвольные задачи. Следовательно, `cargo check`, Clippy, rustdoc-based API analysis и некоторые proc-macro paths — это уже execution boundary, а не просто чтение source. citeturn975785search0  
Это прежде всего правило архитектуры Doctor: L0 lexical/manifest scanners должны работать без build; L1 Cargo producer должен иметь `workspace_trust = trusted` и отчётливо маркировать execution; для external/untrusted patch — sandbox/container/no-network/read-only credentials. Severity `P0` при автоматическом запуске build на untrusted input, иначе policy finding. Regression: fixture `build.rs` пытается создать sentinel outside workspace; native scan не должен его выполнять. Это особенно важно, если Doctor позднее начнёт автоматически «для точности» запускать Clippy.

**`P-RUST-DEPENDENCY-ADVISORY-GAP` — release gate не проверяет известные RustSec advisories/source policy.** Категория: supply chain; dimensions: external dependency integrity. RustSec ведёт advisory database и рекомендует `cargo audit`; cargo-deny дополнительно проверяет advisories, unmaintained/yanked crates, licenses, duplicate bans и разрешённые sources. citeturn821042search0turn821042search1turn821042search6  
Doctor здесь не должен изобретать собственный vulnerability scanner. Producer должен ingest структурированный output `cargo audit`/`cargo deny check`, нормализовать `RUSTSEC-*`, dependency path и direct/transitive status. Severity наследовать из advisory/policy, confidence `high`; suppressions обязаны иметь advisory ID, reason, owner, expiry. Regression — lockfile с известным synthetic/advisory fixture. Сетевой freshness timestamp должен быть частью evidence: зелёный scan со stale database не эквивалентен свежему.

**`P-RUST-DEPENDENCY-COOLDOWN-ABSENT` — автоматическое обновление немедленно принимает только что опубликованную версию.** Категория: supply-chain hardening; dimensions: temporal admission. Rust 1.100 стабилизировал `registry.global-min-publish-age`; Cargo прямо позиционирует его как dependency cooldown, уменьшающий риск некоторых supply-chain атак, но предупреждает, что cooldown не является полной защитой. citeturn885618search0turn885618search2  
Поэтому отсутствие cooldown — **не defect**, а `P2/advisory` для automated dependency-update environments. Detector — `.cargo/config.toml` + CI update jobs. Fix — policy-specific age (`N days`) плюс documented emergency override, RustSec/cargo-deny и review. Не блокировать local development и не применять, если dependencies обновляются только вручную с review.

**`P-RUST-PUBLIC-API-SEMVER-UNGATED` — publishable crate меняет public API без machine check относительно baseline.** Категория: API compatibility; dimensions: parity across versions, external contract. `cargo-semver-checks` анализирует rustdoc JSON и специально предназначен для выявления SemVer-breaking изменений перед публикацией. Он отличает найденные violations от невозможности выполнить анализ через разные exit codes, что Doctor должен сохранить, а не превращать tool failure в «green». citeturn821042search2  
Detector — release/build producer, не source regexp. Severity `P1/high` только для crate с declared compatibility contract и deny-level semver result; private/internal crate — exempt. Regression: baseline fixture с removed public function/trait item; tool failure должен давать `analysis_incomplete=true`, а не zero findings.

**`P-RUST-UNUSED-DEPENDENCY-CARGO100` — dependency hygiene делегируется Cargo, а не самописному grep.** Категория: build complexity/supply chain surface. Cargo 1.100 имеет `cargo::unused_dependencies`, но официальный release note прямо описывает ограничения: предупреждение требует сборки всех релевантных targets и не может надёжно объявить unused `dev-dependencies`. Следовательно, Doctor может ingest это как P2, но не считать неполный target build доказательством отсутствия лишних deps. citeturn885618search0  
Это хороший пример правила, которое не стоит реализовывать ещё одним lexical scanner: использовать owner tool и сохранять `targets_checked`.

## Тесты, concurrency evidence и benchmark hygiene

Статический Doctor не должен пытаться «доказать concurrency correctness» одним grep. Для новых lock/cancellation/atomic patterns целесообразно присоединять **verification recipes**. Miri находит многие классы UB — use-after-free, uninitialized data, invalid values, alignment errors, data races и экспериментальные aliasing violations, — но сам проект Miri подчёркивает, что проверяется лишь конкретное execution и отрицательный результат не доказывает soundness. Для сложных атомарных interleavings Miri прямо рекомендует специализированные инструменты вроде Loom. Loom, в свою очередь, систематически перебирает допустимые interleavings modelled concurrency primitives. citeturn885618search3turn885618search4turn885618search5

**`P-RUST-CONCURRENCY-WITHOUT-MODEL-EVIDENCE`** полезен не как source lint, а как evidence requirement для low-level synchronization code: если код содержит custom atomics/CAS protocol/manual lock ordering и изменение затрагивает invariant, Doctor может запросить `loom`/owner stress-test evidence. Severity `P2/manual`, а отсутствие Loom само по себе не дефект. Trigger: `compare_exchange`, manual memory orderings, multiple interdependent atomics, custom lock-free queue. Regression — Loom model с малым bounded state. В стандарт стоит явно записать: *Loom is requested by risk shape, not mandated for every Mutex.*

Для parser/normalizer/serializer/permission algebra полезен аналогичный **`P-RUST-PROPERTY-TEST-GAP`**: это не «нет proptest — ошибка», а review signal, когда функция имеет большой combinatorial input space и только несколько example tests. Proptest генерирует arbitrary inputs и shrinking минимизирует найденный failing case, но его собственная документация подчёркивает, что finite randomized search всё равно не исследует весь input domain. Поэтому Doctor должен выдавать P2/manual с target rationale: codecs, parsers, canonicalization, round-trip serialization, boundary arithmetic, role/scope set algebra. citeturn885618search6turn885618search7

Более сильный smell — **`P-RUST-WEAK-TEST-ORACLE`**. Сигнатуры: тест вызывает nontrivial command/parser/authorization function и проверяет только `is_ok()`, `is_err()`, `is_some()`, HTTP status или «не panic», но не observable state/output/invariant. Такое может быть нормальным smoke test, поэтому severity `P2`, confidence `heuristic`. Повышать confidence, если рядом нет ни state assertion, ни event/outbox/database assertion, ни equality/property assertion. Canonical fix — assert contract output и negative path. `cargo-mutants` полезен как regression evidence: автор инструмента объясняет, что обычное coverage показывает, что строка была выполнена, а mutation testing — заметили ли тесты изменившееся поведение. Missed mutant при этом может быть эквивалентным, поэтому и этот сигнал нельзя автоматически назвать defect. citeturn821042search3turn821042search7

Для benchmark-кода предлагается **`P-RUST-BENCH-ENVIRONMENT-NOISE`**, но только как `P2/manual`. Criterion статистически анализирует измерения, однако его guidance отдельно обсуждает шум/outliers и влияние окружения; сравнение результатов с разных power/performance режимов или загруженных hosts не должно превращаться в merge-blocking «регрессию». citeturn412028search4 Doctor может ловить особенно явные benchmark smells: network/database calls без isolated local fixture, `thread::sleep`, uncontrolled RNG, wall-clock setup внутри measured closure, setup/teardown смешанные с target operation. Fix — deterministic fixture, setup outside measured closure, stable benchmark environment и сохранённый baseline metadata. Finding должен хранить machine/environment fingerprint, иначе сравнение не воспроизводимо.

`cargo-geiger` следует использовать только как **inventory evidence**, а не как `unsafe == vulnerability` detector. Сам проект подчёркивает, что unsafe требует контекста и статистика использования unsafe сама по себе не говорит, что код небезопасен. Поэтому количество `unsafe` может повышать audit priority, но не severity конкретного finding. citeturn412028search8

Нынешний Doctor уже разделяет severity и confidence; это следует расширить ещё одним измерением **analysis authority**. Lexical finding не должен автоматически становиться `high`, если настоящий Rust type semantics неизвестен. Текущий стандарт прямо предупреждает, что scanner не разрешает типы и не следует по вызовам, поэтому producer provenance должен стать частью finding contract. citeturn854684view1

Особенно полезно использовать rustc/Clippy как **внешних semantic producers**, а не переписывать их правила в JavaScript/Rust regex. Rustc уже знает `let_underscore_lock`, `static_mut_refs`, `unused_must_use`; Clippy знает `let_underscore_future`, `await_holding_lock`, `await_holding_refcell_ref`, `arc_with_non_send_sync`, `unused_io_amount`, unsafe-related lints и numeric casts. При этом Clippy отдельно предупреждает, что restriction lints не следует включать всем набором: их нужно активировать по domain policy. citeturn984086search0turn340052search5turn350218search0

Для concurrency rules имеет смысл добавить optional verification producer `loom`, для unsafe — `miri`, для API releases — `cargo-semver-checks`, для dependency graph — `cargo-deny`/`cargo-audit`, для test quality — `cargo-mutants`. Но failure самого инструмента должен делать отчёт **incomplete/non-authoritative**, а не выдавать ноль findings. Это особенно важно для rustdoc/Cargo-based tools, которые могут не запуститься из-за toolchain/build failures. `cargo-semver-checks`, например, специально различает «SemVer violation» и «check could not complete» отдельными exit statuses. citeturn821042search2

## Предлагаемая схема finding и форма вставки в стандарт

Чтобы не превратить Doctor в шумный «линтер мнений», каждый finding стоит нормализовать примерно в такую модель:

```json
{
  "rule_id": "P-RUST-SELECT-CANCEL-UNSAFE",
  "rule_version": 1,
  "category": "async-cancellation",
  "logic_dimensions": ["order-concurrency", "side-effect-completeness"],
  "severity": "P1",
  "confidence": "heuristic",
  "analysis_level": "L1",
  "producer": {
    "kind": "hir",
    "name": "rustok-doctor-rust",
    "toolchain": "rustc 1.100.0"
  },
  "observation": {
    "path": "crates/.../worker.rs",
    "span": {"line_start": 84, "line_end": 91},
    "signature": "loop > tokio::select! > Semaphore::acquire",
    "resolved_type": "tokio::sync::Semaphore"
  },
  "risk": {
    "claim": "cancellation may discard queue position",
    "not_claimed": "this is not yet proven to violate the owner contract"
  },
  "contract_context": {
    "owner": null,
    "boundary": "worker-admission",
    "requires_manual_owner_check": true
  },
  "evidence": [
    {"kind": "source", "name": "tokio-select-cancel-safety"},
    {"kind": "regression", "status": "missing"}
  ],
  "suppression": null
}
```

Ключевое поле здесь — `observation` отдельно от `risk.claim`. Оно формализует уже существующую философию RusTok: scanner способен доказать синтаксический или типизированный факт, но не обязан из него автоматически доказывать domain defect. Для `P-RUST-UNBOUNDED-CHANNEL`, например, факт вызова `unbounded_channel()` может быть high-confidence, а утверждение «возможен OOM» остаётся heuristic до проверки producer bound. Для `P-RUST-EDITION-RESOLVER-DRIFT` факт `edition=2024 + resolver=2` high-confidence, но поле `defect_confirmed` вообще должно отсутствовать или быть `false`. Такая модель непосредственно соответствует нынешней формулировке стандарта о раздельных impact/confidence и owner verification. citeturn500845view0turn854684view1

Для suppressions нужны не бесконечные `#[allow(...)]`, а структурированные исключения: `rule_id`, `reason`, `owner`, `scope`, `expires`, `contract_evidence`. Existing `P-STALE-ALLOW-LINT` уже показывает, что безусловные и устаревшие suppression сами становятся hygiene debt; поэтому Doctor должен отличать «запретили warning» от «задокументировали законное исключение». citeturn704180view0

Формат каждой новой Markdown-записи разумно сохранить максимально близким к уже существующим новым pattern entries:

```markdown
## P-RUST-SELECT-CANCEL-UNSAFE — Preserve progress across cancellation

- **Status:** General Rust review guidance; not a confirmed RusToK defect.
- **Category:** Async cancellation and progress.
- **Logic dimensions:** Order/concurrency, side-effect completeness, branch completeness.
- **Problem:** A cancellation-unsafe future is recreated inside a repeated
  `tokio::select!`; another winning branch can discard partial progress or queue position.
- **Allowed when:** Cancellation intentionally abandons that operation and its partial
  progress is explicitly irrelevant to the owner contract.
- **Canonical remediation:** Keep/pin state across loop iterations, use a documented
  cancellation-safe primitive, or model partial progress explicitly.
- **Fast detection:** HIR: loop/while -> tokio::select! -> resolved cancel-unsafe call.
  Lexical fallback is heuristic only.
- **Doctor:** P1 / heuristic / L1; never strict-block from regex alone.
- **Regression:** Force the competing branch to win repeatedly; verify no required
  message/progress/permit ordering is lost.
- **Evidence:** Tokio `select!` cancellation-safety contract and primitive docs.
```

Такой template полезнее старого подхода «regex + one-line fix», потому что обязательно содержит **allowed when**, analysis level и отрицательную границу утверждения. Особенно для Rust это критично: `Arc`, `Mutex`, `clone`, `serde(default)`, `mem::forget`, `unsafe`, feature flags и даже cancellation-unsafe futures имеют законные применения, а анти-slop правило становится полезным только тогда, когда умеет описать контекст, в котором оно перестаёт быть smell.

Итоговая архитектура Doctor тогда выглядит как несколько независимых evidence producers, а не один всё более сложный grep-engine: **lexical producer** сохраняет нынешнюю быструю offline-проверку; **rustc/Clippy producer** даёт type-aware high-confidence findings; **Cargo graph producer** проверяет manifests/features/dependency policy; **contract/data-flow producer** связывает security/tenant/transaction/cancellation facts; **dynamic evidence producers** Miri/Loom/proptest/cargo-mutants дают regression evidence, не притворяясь статическим доказательством.
